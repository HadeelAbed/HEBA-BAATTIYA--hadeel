# هيبة بعتية — قاعدة البيانات + الـ API كاملة

هذا الملف يشرح كل شيء تقني: قاعدة البيانات، طريقة الربط، كل واجهات API، ما يحدث بعد كل عملية، وكيف يُخزَّن كل شيء.

---

## 1) قاعدة البيانات (Database)

- **نوع القاعدة:** SQLite حالياً محلياً (ملف `prisma/dev.db`) → سيتم تحويلها لاحقاً إلى **Neon Postgres** (سحابة، للرفع على Vercel).
- **الوصول من الكود:** عبر Prisma ORM فقط (ملف `src/lib/prisma.ts`). لا توجد استعلامات يدوية SQL.
- **السياق (مخطط)** في `prisma/schema.prisma`.

### كيف تَرتبط قاعدة البيانات
كل شيء يعتمد على متغير واحد في `.env`:

```
DATABASE_URL="file:./dev.db"          # محلياً (SQLite)
DATABASE_URL="postgresql://USER:PASSWORD@ep-xxx.aws.neon.tech/dbname?sslmode=require"   # إنتاجاً (Neon)
DIRECT_URL="postgresql://..."         # رابط مباشر (غير مجمّع) من Neon — يضاف في الإنتاج فقط
```

الأوامر:

| الأمر | ماذا يفعل |
|---|---|
| `npx prisma migrate dev` | ينشئ/يحدّث الجداول حسب schema + يحفظ نسخة migration |
| `npx prisma db push` | يدفع الـ schema للقاعدة مباشرة (يُستعمل مع Neon بدون migrations) |
| `npx prisma db seed` | يملأ القاعدة ببيانات تجريبية + حساب الأدمن |
| `npx prisma studio` | فتح المتصفح البصري للقاعدة (يشبه phpMyAdmin) |
| `npx prisma generate` | يحدّث عميل Prisma بعد تعديل schema |

> **ملاحظة:** في الإنتاج على Vercel لا تُستخدم ملفات محلية — القاعدة على سحابة Neon، والـ env كله يُضاف في إعدادات Vercel.

## 2) جداول قاعدة البيانات (المخطط الكامل)

### المستخدمون والمصادقة
| الجدول | الغرض |
|---|---|
| `users` | كل الحسابات (زبون/أدمن/سوبر أدمن). كلمة المرور **مشفّرة** (bcrypt، hash=12). |
| `accounts` | حسابات OAuth (للجوجل مستقبلاً). |
| `sessions` | جلسات NextAuth (غير مستعملة لأننا نستخدم JWT). |
| `verification_tokens` | رموز التحقق من الإيميل (جاهز للمستقبل). |
| `password_reset_tokens` | رموز استرجاع كلمة المرور (email + token + انتهاء). |

**الأدوار:** `CUSTOMER` (افتراضي) / `ADMIN` / `SUPER_ADMIN`.
- `ADMIN_EMAILS` في `.env` (قائمة مفصولة بفواصل): أي إيميل بها يُرقّى تلقائياً لأدمن عند الدخول.
- `SUPER_ADMIN` هو أول حساب تم إنشاؤه بالسيد (من `ADMIN_PASSWORD`) — وحده يستطيع تغيير الأدوار.

### الكتالوج (المنتجات)
| الجدول | الغرض |
|---|---|
| `categories` | التصنيفات (يدعم تصنيفات فرعية عبر `parentId`). |
| `products` | المنتجات (اسم، سعر بالريال، حالة DRAFT/ACTIVE، أعلام مميزة). |
| `product_images` | صور المنتج (ترتيب + صورة أساسية). |
| `product_colors` | ألوان المنتج (اسم + hex). |
| `product_sizes` | المقاسات (XS..XL أو أرقام). |
| `product_variants` | **المخزون الفعلي** لكل (لون+مقاس) — كل متغير له مخزون خاص. |
| `reviews` | تقييمات العملاء. |

### السلة والمفضلة
| الجدول | الغرض |
|---|---|
| `carts` | سلة دائمة: إما لـ `userId` (مسجّل دخول) أو `sessionId` (ضيف عبر كوكي). |
| `cart_items` | عناصر السلة (منتج + لون + مقاس + كمية) — فريد لكل سلة/منتج/لون/مقاس. |
| `wishlist_items` | المفضلة (فريد: مستخدم+منتج). |

### الطلبات
| الجدول | الغرض |
|---|---|
| `orders` | الطلب: الحالة، حالة الدفع، طريقة الدفع، الأسعار (نفري/شحن/ضريبة 15%/إجمالي)، بيانات الشحن **ملفّظة** (لقطة). |
| `order_items` | تفاصيل كل صنف بالطلب مع **لقطة** للسعر والاسم (حتى لو تغيّر المنتج لاحقاً). |
| `coupons` | كوبونات الخصم (نسبة أو مبلغ، حد أدنى، عدد مرات، تاريخ انتهاء). |
| `coupon_redemptions` | من استخدم أي كوبون (سجل). |

### المحتوى والتواصل
| الجدول | الغرض |
|---|---|
| `site_content` | محتوى قابل للتعديل من الأدمن (إعلان، محتوى الصفحات...) — key/value. |
| `newsletter_subscribers` | مشتركو النشرة. |
| `contact_messages` | رسائل نموذج "تواصل معنا". |

### العناوين
`addresses` — عناوين المستخدم (منزل/عمل، افتراضي). الطلب ينسخ بيانات العنوان في `orders.ship_*` حتى لو حُذف العنوان لاحقاً.

## 3) كل واجهات API (مختصرة)

> كل `route.ts` تحت `src/app/api/`. **عام:** المسارات التي تتطلب دخولاً تُرجع 401 بدون جلسة، ولوحة الأدمن تتطلب ADMIN/SUPER_ADMIN.

### المصادقة (NextAuth)
| المسار | الطرق | الوصف |
|---|---|---|
| `/api/auth/[...nextauth]` | GET/POST | قلب NextAuth: تسجيل دخول، جلسات، تسجيل خروج. |
| `/api/auth/csrf` | GET | رمز CSRF الضروري قبل الدخول. |
| `/api/auth/callback/credentials` | POST | تسجيل الدخول بالإيميل+الباسورد. |
| `/api/auth/session` | GET | قراءة الجلسة الحالية. |
| `/api/auth/signout` | POST | تسجيل الخروج. |
| `/api/register` | POST | إنشاء حساب جديد (اسم، إيميل، هاتف، باسورد). |
| `/api/auth/forgot-password` | POST | إرسال رابط استرجاع كلمة المرور (يرسل إيميل عبر SMTP أو يطبع للكونسول في التطوير). |
| `/api/auth/reset-password` | POST | تنفيذ كلمة المرور الجديدة بالرمز. |

### المتجر
| المسار | الطرق | الوصف |
|---|---|---|
| `/api/products` | GET | قائمة المنتجات (بحث، تصفية، ترتيب). |
| `/api/products` | POST | (أدمن) إنشاء منتج. |
| `/api/categories` | GET | التصنيفات. |
| `/api/cart` | GET | عناصر سلة المستخدم الحالي. |
| `/api/cart` | POST | إضافة عنصر (أو زيادة كميته). |
| `/api/cart` | DELETE | تفريغ السلة كاملة. |
| `/api/cart/[id]` | PATCH | تعديل الكمية (و0 تحذف). |
| `/api/cart/[id]` | DELETE | حذف عنصر واحد. |
| `/api/wishlist` | GET/POST | عرض/إضافة المفضلة. |
| `/api/coupons` | POST | التحقق من كوبون وتطبيقه. |
| `/api/reviews` | GET/POST | التقييمات. |

| `/api/newsletter` | POST | الاشتراك بالنشرة. |
| `/api/checkout` | POST | **إنشاء الطلب** (يتطلب تسجيل دخول). حالياً فقط الدفع عند الاستلام يُفعَّل؛ البوابات تُضاف لاحقاً. |
| `/api/orders` | GET | طلبات المستخدم الحالي. |

| المسار | الطرق | الوصف |
|---|---|---|
| `/api/admin/analytics` | GET | إحصائيات (مبيعات، طلبات، عملاء، أفضل المنتجات). |
| `/api/admin/products` | GET/POST/PATCH/DELETE | إدارة المنتجات. |

## 4) ماذا يحدث بعد كل عملية رئيسية (تدفّق البيانات)

### إنشاء حساب (`/api/register`)
1. يتحقق من البيانات (zod) → يرفض لو البريد موجود.
2. **يُشفّر كلمة المرور** بـ bcrypt (12 جولة) → لا تُخزَّن أبداً نصية.
3. يُنشئ صف `users` بالدور `CUSTOMER`.
4. المتصفح يسجّل الدخول تلقائياً (Credentials) → تُنشأ جلسة JWT (كوكي `authjs.session-token`).
5. يتحوّل إلى `/` (أو `/admin` لو الإيميل في `ADMIN_EMAILS`).

### تسجيل الدخول (`/api/auth/callback/credentials`)
1. يقرأ الإيميل+الباسورد → يبحث عن المستخدم.
2. يقارن الباسورد المشفّر (bcrypt.compare).
3. عند النجاح: JWT callback يضيف `role` للجلسة (ويرقّي الإيميلات المدرجة في `ADMIN_EMAILS`).
4. عند النجاح: سلة الضيف تُدمج تلقائياً في سلة المستخدم (انظر السلة).
5. المتصفح يتوجّه حسب الدور: أدمن → `/admin`، زبون → `/`.

### السلة (Cart)
- **الضيف:** عند أول إضافة تُنشأ سلة في القاعدة مرتبطة بكوكي `hb_cart` (سري/httpOnly، يعيش 30 يوماً).
- **المسجّل:** السلة مرتبطة بـ `userId`.
- **بعد الدخول:** تُدمج سلة الضيف في سلة المستخدم (تجمع الكميات للعناصر المكررة) ثم تُحذف سلة الضيف وتُمحى الكوكي.
- **محلياً (localStorage):** المتصفح يحفظ نسخة من السلة (`hb-cart` في localStorage) كشبكة أمان — السلة تعود حتى بعد تحديث الصفحة. تُمسح عند تسجيل الخروج.
- كل تعديل (إضافة/كمية/حذف) يُرسل للخادم (`/api/cart`...) وتُحدَّث القاعدة.

### إتمام الطلب (`/api/checkout`)
1. يجب أن يكون المستخدم مسجّلاً (غير مسجل → 401 → توجيه للتسجيل).
2. يأخذ عناصر السلة من العميل (المنتجات، الكميات، الألوان/المقاسات) → يتحقق من توفرها.
3. يحسب: المجموع الفرعي ← خصم الكوبون (إن وجد، ويسجّل استخدامه) ← ضريبة 15% ← شحن (75 ر.س، مجاني فوق 2000).
4. يُنشئ صف `orders` + صنف لكل `order_items` (بلقطات) → يُنقص **المخزون** من المتغيرات.
5. **الدفع عند الاستلام فقط** يُفعَّل حالياً (`paymentStatus=PENDING`, `status=CONFIRMED`).
6. يُرجع رقم الطلب → يعرض صفحة التأكيد ويُفرّغ السلة.
   > (عند ربط بوابة: هذه النقطة تتحول إلى إنشاء جلسة دفع → توجيه للبوابة → Webhook يؤكد → يُحدَّث الطلب إلى PAID.)

### استرجاع كلمة المرور
1. `/forgot-password` ← إنشاء رمز عشوائي + تخزينه في `password_reset_tokens` (انتهاء بعد ساعة) + إرساله بالإيميل.
2. المستخدم يفتح رابط الاسترجاع → يدخل كلمة جديدة → `/reset-password` يتحقق من الرمز والتاريخ → **يحدّث الباسورد (مشفّر)** → يحذف الرمز.

### المفضلة
- لا تُخزَّن للضيف (تحتاج تسجيل دخول) — الزبون يحفظها في `wishlist_items` (مستخدَم + منتج فريد).
- المتصفح يحفظ نسخة محلية بـ localStorage لحفظها مؤقتاً.

## 5) أين يُخزَّن كل شيء؟

| المعلومة | المكان |
|---|---|
| الحسابات، المنتجات، الطلبات، السلة الخادمية، التقييمات، الكوبونات، المحتوى | **قاعدة البيانات** (SQLite/Neon) |
| الجلسة (من دخّل) | **كوكي** `authjs.session-token` (JWT مشفّر، httpOnly) |
| سلة الضيف | **قاعدة بيانات** مرتبطة بكوكي `hb_cart` |
| نسخة السلة كاحتياط | **localStorage** باسم `hb-cart` |
| المفضلة محلياً (مؤقت) | **localStorage** باسم `hb-wishlist` (مثال) |
| آخر طلب معروض في صفحة التأكيد | **sessionStorage** `hb-last-order` |
| الصور | مجلد `public/` حالياً (لاحقاً Cloudinary) |
| كلمة المرور | **bcrypt hash** — لا تُخزَّن نصية أبداً |

## 6) متغيرات البيئة المطلوبة (ملخص)

```
DATABASE_URL          # رابط القاعدة (SQLite محلي / Neon في الإنتاج)
DIRECT_URL            # الرابط المباشر من Neon (إنتاج فقط)
AUTH_SECRET           # سرّ تشفير الجلسات
AUTH_TRUST_HOST=true  # ضروري في next start/Vercel
NEXT_PUBLIC_SITE_URL  # رابط الموقع
ADMIN_EMAILS          # إيميلات الأدمن (مفصولة بفواصل)
ADMIN_PASSWORD        # باسورد الأدمن الرئيسي (للسيد)
EMAIL_SERVER_*        # SMTP لرسائل الاسترجاع/الطلبات (اختياري — بدونها تُطبع بالكونسول)
```

كامل الأسماء في `.env.example`.
